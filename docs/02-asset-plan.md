## 3. GIF → Codex v2 图集

### 3.1 素材准入

一条 GIF 要能进图集，至少满足：

- 单角色、全身、机位固定、无镜头运动；
- 背景为纯色/近似纯色（白、绿幕最佳），没有渐变和地面阴影；
- 角色不被裁切，脚底位置稳定；
- 动作语义与目标状态一致（挥手就是挥手，不要拿待机冒充）；
- 帧数 ≥ 目标帧数；多了可以均匀抽帧，少了不能硬凑。

### 3.2 处理流程（本仓库已脚本化）

```powershell
# 1. 抽帧 + 去背景 + 裁剪 + 缩放到安全区 + 对齐基线 → 透明 PNG
python tools/import_gif.py `
  --gif assets/salt-wave.gif `
  --state waving `
  --out build/frames/waving `
  --max-frames 4 `
  --tolerance 34 `
  --despill

# 2. 用帧目录合成图集（缺的状态自动回退到程序化帧）
python tools/build_atlas.py --frames-dir build/frames

# 3. 硬规格校验
python tools/validate_atlas.py pets/salt/spritesheet.webp --json-out build/validation.json
```

`import_gif.py` 做的具体事：

1. 用 Pillow 逐帧读取 GIF（处理 disposal，统一转 RGBA）；
2. 取四边像素中位数估计背景色；
3. 从边界做**洪水填充**，只删除与边界连通的背景，避免把角色内部的白色围裙一起抠掉；
4. 可选 `--despill`：把半透明边缘像素往背景色反方向拉，减少白边/绿边；
5. 按 alpha 裁到内容 bbox；
6. 等比缩放到 **176×196** 安全框内（单帧 192×208，四周留边，防止缩放/描边贴边）；
7. 底部对齐到 **y=202** 基线，水平居中；
8. 输出 `00.png …`，供 `build_atlas.py` 按数字顺序读取。

### 3.3 去阴影 / 文字 / 漂浮特效

脚本只解决「纯色背景 + 连通背景」。以下情况需要手工或额外蒙版：

| 问题 | 处理 |
| --- | --- |
| 地面阴影 | 在源图阶段不要画；已有阴影时，用椭圆选区手动擦除，或把阴影颜色并入背景 key 后再洪水填充 |
| 文字/水印 | 不要使用带文字的素材；无法去除时换源，不要用修补工具糊 |
| 速度线/尘土/星星 | 属于「漂浮特效」，必须整层删除；宁可少几帧 |
| 背景渐变 | 洪水填充会残留；改用 `--no-key` 后手工蒙版，或用抠图模型生成 alpha |
| 半透明披发/尾巴 | 不要用硬阈值；保留 alpha，`--despill` 只做边缘去色 |

### 3.4 排列到 8×11 网格

`build_atlas.py` 会：

- 新建 1536×2288 透明画布；
- 按 `row × 208`、`col × 192` 放置；
- 每个状态只放前 N 帧，**未用格保持全透明**；
- 第 9–10 行放 16 个方向（`build/frames/look/00.png…15.png`，没有就用程序化方向）；
- 导出 WebP（quality 92、method 6、保留 alpha），并生成 `atlas-report.json`、QA 总览、预览图、托盘图标。

### 3.5 帧数与时长

| 状态 | 帧数 | 建议单帧时长 | 循环 |
| --- | ---: | --- | --- |
| idle | 6 | 200 ms | 是 |
| running-right/left | 8 | 100 ms | 是 |
| waving | 4 | 180 / 150 / 150 / 180 ms | 否 |
| jumping | 5 | 140 / 110 / 150 / 130 / 180 ms | 否 |
| failed | 8 | 170 ms | 否（播完回 idle） |
| waiting | 6 | 220 ms | 是 |
| running | 6 | 150 ms | 是 |
| review | 6 | 180 ms | 是 |

这些值写在 [`pets/salt/pet.extended.json`](../pets/salt/pet.extended.json) 的 `tracks` 里；官方 Codex 用自身的固定时序，第三方渲染器可读扩展。

### 3.6 左右移动

`running-left` 可以镜像 `running-right`，前提是：

- 角色没有单侧脸纹、文字、单侧挂件、方向性光源；
- 镜像后尾巴/围裙/盐罐的安装意义不变。

莎露朵的女仆装与盐罐基本对称，允许镜像。`salt_art.py` 就是这么做的；手工素材可用 `--mirror`。

## 4. 只有一张基准图时的程序化补全

参考 Codex Pet 生成器的思路：**一张 canonical base + 分层 + 确定性变换**，而不是让模型逐帧重画。本仓库的占位图就是这套方法的可运行示例。

### 4.1 分层

至少拆成：

```text
tail（在身体后）
back_hair（在身体后）
legs / shoes
body（裙、围裙、领结、铃铛、盐罐）
arms（可独立旋转）
head（脸、耳、眼、眉、嘴、刘海、发饰）
```

眼睛单独一层，便于眨眼遮罩；瞳孔单独一层，便于 16 向。

### 4.2 允许的变换

| 变换 | 幅度 | 用途 |
| --- | --- | --- |
| 整体平移 | ±16 px（跳跃） | 呼吸、跳跃 |
| 头部平移 | ±4 px | 视线、张望 |
| 头部旋转 | ≤ 6° | 歪头、检查 |
| 尾巴旋转 | ±25° | 摇摆、失败下垂 |
| 耳朵旋转/下压 | ≤ 20° | 警觉、失落 |
| 手臂旋转 | ±45° | 挥手、揉面 |
| 眨眼遮罩 | 0–100% | idle/waiting/review |
| 瞳孔位移 | ±4 px | 16 向视线 |
| 水平镜像 | 整帧 | running-left |

### 4.3 不允许的变换

- 整只角色旋转、倾斜、拉伸、透视变形来伪造视线或动作；
- 逐帧缩放（会「忽大忽小」）；
- 用 AI 插帧把 4 帧硬补成 8 帧（容易糊、身份漂移）；
- 把不同来源的帧混排（比例/光位/线宽不一致）。

### 4.4 每个状态的程序化配方

- **idle**：`y = sin(t)·1.3`；第 2 帧半闭眼、第 3 帧闭眼；尾巴 `sin(t)·9°`；第 4 帧耳朵轻抖。
- **running-right**：身体右倾 2 px，腿相位 `t` 与 `t+π`，手臂反相摆动，尾巴后扬 13±6°；左移整帧镜像。
- **waving**：左手从肩部抬到脸颊外侧，手腕在 4 帧里外摆/内收；头歪 4°、脸红、开口。
- **jumping**：y 偏移 `[+8,-2,-16,-5,+4]`，腿收起 `[6,3,8,4,0]`，双手在顶点上举；只改位置不改尺寸。
- **failed**：头下移 3 px、耳朵下垂、半闭眼、泪滴（第 3 帧起）、尾巴 -26°、轻微左右摇。
- **waiting**：双手在身前交叠、头歪 5°、第 3 帧眨眼、耳朵竖起、尾巴慢摆。
- **running**：前倾 2 px、双手在身前交替揉面、眼睛压 15%、汗滴、尾巴轻甩。
- **review**：手托下巴、头歪 -5°、瞳孔按 `[-2.6, 0, +2.6, 0, -2.6, 0]` 扫读、轻微点头。
- **16 向**：`vx=sin(θ), vy=-cos(θ)`；瞳孔 `(vx·4.2, vy·3.0)`，头 `(vx·3.4, vy·1.6)`，头倾斜 `vx·3°`；上看睁眼、下看压上眼睑；正面用 `idle`。

这套配方在 [`tools/salt_art.py`](../tools/salt_art.py) 里可直接改参数；改完 `python tools/build_atlas.py` 即可看到新图集。

## 5. 验收清单

- [ ] 1536×2288、8×11、192×208、RGBA/透明。
- [ ] 每行帧数 = `[6,8,8,4,5,8,6,6,6]`，未用格全透明。
- [ ] 9–10 行 16 格全部有内容，方向顺序正确。
- [ ] 四角透明，没有烘焙背景。
- [ ] 每帧内容不贴边（≥2 px），脚底基线一致。
- [ ] 没有阴影、文字、速度线、尘土、漂浮符号。
- [ ] 1× 尺寸下角色仍能读出猫耳、发色、围裙、尾巴。
- [ ] 相邻帧没有跳位、翻面、忽大忽小；尾巴/耳朵连接点不穿模。
- [ ] 文件 ≤ 16 MiB；WebP 在深色/浅色背景下都无彩边。
- [ ] 授权链路可追溯：谁画的、允许什么用途、是否允许分发。

## 6. 如果某个状态缺素材

当前 9 个状态都已有表情包帧；如果以后替换/扩展时缺状态，按优先级降级，**不要空着**：

1. 参考第 0 节的选帧表，从同一位作者的表情包里找语义接近的 GIF；
2. 用单张自制/授权基准图 + `salt_art.py` 的变换配方补该状态；
3. 只补 `idle` + `waving` + `jumping` + 16 向，其余状态复用近似帧并在扩展清单里注明；
4. 发起约稿或购买授权素材，按第 2.3 节简报交付；收到后逐状态替换，不需要改渲染器。
